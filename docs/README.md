## 阅读顺序建议

**新人接手** → `PRD.md` §1–§4（定位与概念）→ §5 挑相关模块 → `DEPLOYMENT.md` §0–§3（环境）
**要发布** → `DEPLOYMENT.md` §5 标准发布流程（含「先备份再 db push」的顺序要求）
**线上出问题** → `DEPLOYMENT.md` §6 运维命令 → §7 三个已知坑
**改会议/权限** → 先读模块级 PRD，再回 `PRD.md` §5 对应章节确认与其它模块的耦合

## 维护约定

- 这几份是**现状文档**，不是提案。代码变了要同步改，否则下一轮开发会被旧描述误导。
- 涉及凭据（密钥内容、`.env` 真实值、数据库口令）**一律不写进文档**，只写位置与文件名。
- 部署事实以服务器实测为准；仓库内配置文件与服务器不一致时，`DEPLOYMENT.md` §7 已记录差异原因，不要在文档里「抹平」它。
