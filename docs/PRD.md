## 1. 产品定位

### 1.1 一句话

**用 AI 把「群里的聊天」「会上说的话」「脑子里的想法」变成可追踪的项目、任务和纪要，并让每个人只看自己该看的那一部分。**

### 1.2 解决的四个具体问题

| # | 现状问题 | 系统对策 |
| --- | --- | --- |
| 1 | 进展散落在钉钉群里，管理者要靠翻聊天记录才知道项目到哪了 | AI 定时抓群消息 → 提炼为「进展」条目 → 首页绿色展示，可一键转任务 |
| 2 | 周报写了没人看，看了没人汇总，汇总了不落地 | 日报/周报 AI 生成 + 公司周报聚合 + AI 总览；项目周报聚合页部门负责人置顶 |
| 3 | 会上派的活靠记性，事后无法追溯「谁答应什么时候交」 | 会议纪要强制落到 `TODO/RISK/PENDING` 条目并带时间节点，自动进任务与提醒 |
| 4 | 文档、SOP、经验各存各的，换个人就重踩一遍坑 | 知识库四档可见性 + 复盘 AI 汇总 → 提 SOP 候选 → 人工确认生效 |

### 1.3 设计原则（贯穿全系统的隐含规则）

1. **AI 只提议，不代替人决策**：所有 AI 产出（进展、周报、纪要、SOP、规划）都要人确认才落库或对外发送。
2. **先事实后动作**：AI 助手发起任何通知/催办前，必须先查真实数据（缺交名单、逾期清单），禁止编造人名与数字。
3. **可见性即权限**：所有列表查询在后端按角色+项目成员+部门关系过滤，前端隐藏菜单不算权限控制，只是体验。
4. **留痕优先**：保密项目的一切访问、规则已阅、审批加签、AI 每次调用都写日志。
5. **手机可用**：核心链路（首页待办、写日报、助手对话、活动签到）在手机上单列布局，支持 PWA 安装。

## 2. 用户角色与权限

### 2.1 角色定义

| 角色 | 枚举值 | 层级 | 来源 | 典型职责 |
| --- | --- | --- | --- | --- |
| 系统管理员 | `ADMIN` | 3 | 系统首个注册用户自动成为；可后台任命 | 组织架构、审批、保密配置、全站数据 |
| 部门负责人 | `DEPT_LEADER` | 2 | 管理员任命（依附部门） | 本部门成员/周会/周报、部门统计 |
| 项目负责人 | `PROJECT_LEADER` | 1 | 管理员任命 | 所负责项目的成员/任务/进展/健康度 |
| 普通成员 | `MEMBER` | 0 | 自助注册或被创建 | 自己的日报、任务、会议、文档 |

### 2.2 权限矩阵（主要能力）

| 能力 | ADMIN | DEPT_LEADER | PROJECT_LEADER | MEMBER |
| --- | :-: | :-: | :-: | :-: |
| 全站项目/成员/会议可见 | ✅ | 本部门 | 自己项目 | 参与的项目 |
| 审批立项 / 加签 | ✅ | ✅（所辖） | — | — |
| 任命角色、重置密码、停用账号 | ✅ | — | — | — |
| 会议考勤统计 | ✅ | — | — | — |
| 会议关联群配置 | ✅ | ✅ | — | — |
| 会议发起 / 纪要 / 派活 | ✅ | ✅ | ✅ | 参与即可 |
| 保密开关、NDA 模板 | ✅ | — | — | — |
| 保密项目内容 | ✅（留痕） | 需签 NDA 且为成员 | 需签 NDA 且为成员 | 需签 NDA 且为成员 |
| AI 助手全部工具 | ✅ 20 个只读 + 14 类动作 | 团队级工具 | 项目级工具 | 本人级工具 |
| 团队排行（看他人名字与数值） | ✅ | ✅ | 自己项目 | ❌ 仅看自己名次 |

### 2.3 三个容易误解的规则

1. **未分配部门的 MEMBER 被全站锁定**：只能进 `/pending` 缺省页，无法访问任何业务页（路由闸 + 页面不挂载）。ADMIN 不受限（首用户本无部门），DEPT_LEADER / PROJECT_LEADER 不受限（权限依附于已任命关系）。
2. **身份预览不是登录**：管理员可「以某人身份预览」，此时顶部常驻黄色横幅，退出后恢复管理员 token。用于排查「他说看不到」类问题，不是赋权。
3. **项目主要关联部门的负责人有额外可见性**：项目文档、项目文件对「主要关联部门负责人」可见——但保密项目下这条被**取消**。

## 4. 核心概念词典

| 术语 | 定义 | 关键规则 |
| --- | --- | --- |
| **进展** | 从钉钉群消息 + 成员日报/周报中由 AI 提炼的单条结论，首页**绿色**显示 | 当天进展加深高亮；已转任务的转**蓝色**并带徽标；同项目内可拖拽合并；点击可「从进展创建任务」 |
| **播报** | 首页跑马灯，滚动提示待办/逾期/会议/截止 | 悬停暂停并展开该条详情，点击直达对应列表或详情 |
| **智能录入** | 首页一个输入框，一段自然语言自动判定为日报/周报/任务/灵感并抽取字段落库 | AI 判别 + 抽取；判定不确定时按最可能的类别处理并可改 |
| **重点工作任务** | 首页高亮展示的当前关键任务 | 支持快捷改状态与截止时间，写活动记录 |
| **PBC** | 月度个人业务承诺：本月计划事项 + 分值，**合计必须 = 100** | 本人填写 → 上级打分 → 排行；可 AI 分解为任务（带建议截止日） |
| **日报看板 / 工时统计** | 团队日报提交情况矩阵 / 工时排行（周/月/累计） | 与「我的工作时间安排」联动：没排班的人不进「应发」名单 |
| **会议层级** | `DEPT` 部门周会 / `COMPANY` 公司 leader 周会 / `PROJECT` 项目会 / `PERSONAL` 临时会 | 不同层级参会人来源与材料要求不同 |
| **会议条目** | `TODO` 待办 / `RISK` 风险 / `PENDING` 会后待处理 | **必须带完成时间节点**，可指派到人并生成任务 |
| **活动（Meeting 的扩展形态）** | 带签到、分组、答题、点赞、加分、公开链接的会议 | 对外页免登录，支持密码；考勤可补签 |
| **SOP** | 标准经验/流程 | 三个来源（复盘提取/团队记录提取/人工），状态 `CANDIDATE → APPROVED / REJECTED`，**只有 APPROVED 才算生效库** |
| **复盘** | 项目或事件的回顾 | 两种形态：`STRUCTURED`（固定 5 问）/ `GENERAL`（导入总结）；可 AI 汇总成报告并提 SOP |
| **项目健康度** | AI 依据任务延期、交付窗口、里程碑算出的 `GREEN/YELLOW/RED` | 仅作建议，不自动改项目状态 |
| **保密项目** | 打了 `confidential` 标记的项目 | 仅已签 NDA 的成员 + ADMIN（留痕）可见；进展不在首页对非成员显示；不进 AI 问答范围 |
| **NDA 版本** | 全站一份保密协议模板，改内容即升版本 | 签署记录绑定具体版本；改版**不强制**已签者重签 |
| **项目规则** | 项目内发布的规则，成员需「已阅」 | 手动点已阅可附一句说明；修订后**不强制**重新已阅，也不保留历史版本表 |
| **交付窗口 / 里程碑** | 项目排期与关键节点 | 排期项与里程碑参与健康度计算 |

## 5. 功能需求

> 每章格式：**目标 → 功能点 → 关键规则 → 验收标准**。标注「已实现」的均为现状。

### F1 认证与组织

**目标**：把「谁能用、能用哪些」管住，同时不挡住新人第一次进来。

| 功能点 | 说明 | 状态 |
| --- | --- | --- |
| 登录 | 邮箱或用户名 + 密码，JWT（默认 7 天） | 已实现 |
| 自助注册 | 注册即 `MEMBER`，无部门 → 进 `/pending` 缺省页等待分配 | 已实现 |
| 管理员建号 | 必填用户名，首次登录**强制改密**（`mustChangePassword`） | 已实现 |
| 改密 / 找管理员重置 | 本人改密；管理员可重置任意账号 | 已实现 |
| 身份预览 | 管理员以他人身份浏览，顶部横幅 + 一键退出 | 已实现 |
| 组织准入闸 | `pendingOrg` 时除 `/pending`、`/login`、公开页外全部重定向 | 已实现 |
| 部门管理 | 增删改部门、成员归属、多部门（主部门 + 额外部门）、部门负责人 | 已实现 |
| 汇报关系 | `reportsTo` 自引用汇报树，无上级者为根（总负责人） | 已实现 |
| 工号 | 按注册顺序自动分配连续整数，仅展示用 | 已实现 |

**关键规则**
- 首个注册用户自动成为 `ADMIN`，此后注册一律 `MEMBER`。
- 停用（`active=false`）账号不能登录，历史数据保留。
- 部门删除时成员 `departmentId` 置空（`SetNull`），不级联删人。

**验收**：新注册用户登录后只看到 `/pending`，页面显示姓名/邮箱/注册时间 + 刷新按钮；管理员分配部门后点刷新自动跳回首页。

### F2 首页（工作台）

**目标**：打开就知道「今天该干什么、项目到哪了、有什么在等我」。

| 区块 | 内容 | 交互 |
| --- | --- | --- |
| 欢迎横幅 | 问候 + 今日概览：待办数 / 逾期数 / 今日进展数 | 点击分别跳任务筛选、逾期列表、定位进展区 |
| 播报（跑马灯） | 本月待完成任务、逾期、待参加会议、最近会议、最近截止 | 悬停暂停 + 展开详情；点击直达 |
| 智能录入 | 一个输入框，自然语言 → 日报/周报/任务/灵感 | AI 判别并抽取字段，落库后可改 |
| 重点工作任务 | 当前关键任务列表 | 快捷改状态/截止，写活动记录 |
| 我的项目进展 | **绿色** AI 提炼条目，按消息日倒序 | 点击→从进展创建任务；拖拽合并；已转任务变蓝 |
| 团队公告 | 公告列表 + 置顶；含「近 3 天会议活动」自动条目 | 点击展开详情；管理员可发布 |
| 全公司榜单 | 最近一次 PBC 排行 + 一卡两页轮播（本周工时 / 本月日报数） | 默认前 10，可展开 |
| 我的部门 | 部门成员与负责人 | 点击进员工画像 |
| 全部功能 | 功能入口九宫格 | 直达各页 |

**关键规则**
- 进展排序：有进展的按「最新一条进展的消息时间」倒序排前，无进展的按项目 `updatedAt` 沉底（进展不 touch 项目）。
- 保密项目：未签 NDA 的成员看到的是「签协议后可见」提示，而不是空白（避免误判为「无进展」）。
- 手机端顺序重排为：待办 → 录入 → 播报 → 重点工作 → 进展 → 公告/榜单/入口。

**验收**：新用户首次进入 3 秒内看到待办与进展；手机端单列无横向滚动；点击绿色进展条能创建任务且创建后条目变蓝。

### F3 工作管理（日报 / 周报 / PBC / 看板 / 工时）

**目标**：把「写报告」从负担变成半自动，并让管理者一眼看到谁交了谁没交。

| Tab | 功能 | 关键规则 |
| --- | --- | --- |
| 日报 | 手写或 AI 生成；三段式（已完成 / 后续计划 / 需协调问题）；可补录历史日期；带工时 | 手写提交时 AI 纠错整理 + 智能归属项目 + 提取工时；同日重复提交自动追加合并 |
| 周报 | AI 生成或手写；按「本周成果 / 进行中 / 风险与下周计划」 | 可一键发到钉钉群；可补发往期（`periodStart`） |
| PBC 月计划 | 本人按自然月填「事项 + 分值」 | **分值合计必须 = 100**，可反复编辑；上级打分；可 AI 分解为任务 |
| 日报看板 | 团队矩阵：谁哪天交了什么、缺哪天 | 与工作时间安排联动，未排班者不计缺交 |
| 工时统计 | 周/月/累计排行 | 与榜单同源，口径一致 |
| 我的工作时间安排 | 按周设置固定工作时段（预设上午/下午/晚上或自定义时间） | 决定「当天是否属于应发日报人员」；AI 助手可代改（仅本人） |

**关键规则**
- 视角切换：ADMIN / DEPT_LEADER 可切到「团队成员」查看下属日报/周报/PBC。
- 工时只能来自日报，没有日报就没有工时，也就进不了工时榜。
- 日报正文 `content` 必须是可支撑的事实，AI 不得编造工作项（提示词级约束）。

**验收**：写一篇日报后首页工时榜与「我的工时」同步变化；未排班日不产生缺交提醒。

### F4 项目

**目标**：项目是「进展、任务、会议、周报、文档」的聚合容器，也是权限边界。

| 功能 | 说明 |
| --- | --- |
| 项目列表 | **统一按部门分组展示**（组序=组织架构 sortOrder→createdAt）：每个项目归入其「主部门」（关联部门中组织顺序最靠前的一个），未关联部门的归入「未归类」沉底；回收站保持平铺。另可下拉筛选单一部门。卡片含状态、健康度、成员数、任务数 |
| 立项审批 | 创建默认 `PENDING`（仅 owner + 审批人 + ADMIN 可见）→ 同意转 `ACTIVE` / 驳回 `REJECTED`（owner 可改后重新提交） |
| 加签共同审批 | 可追加共同审批人，任一驳回即驳回；记录各自结论 |
| 项目详情 Tab | 概览 / 进度 / 日报 / 任务 / 会议 / 周报 / 文档 |
| 里程碑与排期 | 里程碑 + 排期项，参与健康度计算 |
| 项目周报 | 聚合成员周报，**部门负责人置顶**，顶部 AI 总结（总览/进展/下周/风险/需关注） |
| 健康度 | AI 分析：任务统计 + 里程碑 + 时间窗口 + 近期进展 → 0-100 完成度 + `GREEN/YELLOW/RED` |
| 项目规则 | 发布规则 → 成员「已阅」（可附说明）→ 已阅名单；修订不强制重阅 |
| 保密标记 | 仅 ADMIN 可拨；拨开后触发 NDA 签署与访问留痕 |
| 回收站 | 软删除项目可恢复 / 彻底清除 |
| 项目文档与文件空间 | 在线文档 + 任意附件上传/下载；可见性四档 + 对外分享 |

**关键规则**
- 项目关联部门为**可选多选**（`ProjectDepartment`），影响列表分组与部门负责人可见性；未关联部门的项目进「未归类」组。
- `PENDING` / `REJECTED` 项目**不参与**首页、任务、成员、排行等所有可见性口径。
- 项目成员分 `OWNER` / `MEMBER`，负责人可调成员职位（`position`）与转移 owner。
- 保密项目的四项收紧：① 取消主要关联部门负责人默认可见；② 进展不在首页对非成员显示；③ 暂停每日进展群发钉钉；④ 不进 AI 问答可答范围。

**验收**：新建项目后其他人完全查不到（含接口层）；驳回后 owner 能改并重提；保密项目未签 NDA 时接口返回 403 而非空列表。

### F5 任务

**目标**：进展、会议、AI 助手都能落到「一条可追踪的任务」。

| 功能 | 说明 |
| --- | --- |
| 列表视图 | 按项目/负责人/状态/优先级/标签筛选；我的待办、逾期视图 |
| 看板视图 | 按列拖拽改状态，列可增删改 |
| 任务详情 | 描述、附件、评论、活动记录（谁改了什么） |
| 快捷操作 | 状态、截止时间、优先级、指派人 |
| 从进展创建 | 首页/项目页点绿色进展 → 建任务并回写关联（条目变蓝） |
| 会议待办落地 | 会议 `TODO` 条目指派后生成任务，带时间节点 |
| 逾期提醒 | 队列扫描逾期任务，推站内信 + 钉钉私聊 |

**关键规则**
- 状态：`TODO / IN_PROGRESS / DONE`；标 `DONE` 自动置进度 100%。
- 优先级：`LOW / MEDIUM / HIGH / URGENT`。
- AI 助手改任务只能改「状态 / 截止时间 / 优先级」三项；改派负责人必须走新建。
- 任务标题匹配到多条时，AI 必须回候选清单追问，不得自行猜测。

**验收**：看板拖拽后列表视图状态同步；逾期任务在首页播报与任务页同时出现；回收站项目的任务不计入「我的待办」。

### F6 会议与活动

> 详细方案见 `docs/meeting-prd.md`（v1.2），此处只写现状要点。

**目标**：把线下开会流程整体搬到线上，形成「材料 → 讨论 → 派活 → 纪要 → 提醒 → 完成」闭环。

| 功能 | 说明 |
| --- | --- |
| 分层会议 | `DEPT` 部门周会 / `COMPANY` 公司 leader 周会 / `PROJECT` 项目会 / `PERSONAL` 临时会 |
| 周会自动生成 | 部门可配**多场**周会（`DepartmentMeetingSlot`：每周几 + 几点 + 是否自动） |
| 冷启动策略 | 首场进草稿 + 私聊负责人发布；负责人发布过一次后转 `autoPilot` 自动发群 |
| 会前材料 | 参会人提交或系统自动读取周报；可标记已读、催办 |
| 点评 | 主持/管理员对某份材料写意见，不覆盖原文，独立留痕 |
| 会议条目 | `TODO` / `RISK` / `PENDING`，必须带完成时间，可指派 |
| 纪要 | 可指派撰写人；发布后推送给参会人 |
| 考勤 | 签到 / 补签 / 迟到判定；统计到人 |
| 活动扩展 | 分组（含组长）、答题测验、点赞、加分（需审批） |
| 对外页 | 免登录凭 token 进入，可设访问密码；支持扫码签到、答题、看小组得分 |
| 提醒 | 每 5 分钟扫描：开始提醒 + 材料催办；20:00–07:00 禁发（开始提醒豁免） |
| 关联群配置 | 公司级/部门级配置发群目标 |

**关键规则**
- 同项目/同会议内周报互见。
- leader 周会取「部门汇总周报」，不是个人周报。
- 会议规则负责人随时可改，改了不影响已发布的那一场。
- 不做：音视频、屏幕共享、钉钉日历双向同步、复杂重复规则（每两周/每月第 N 个周三/跳节假日）、Word/PDF 导出、外部参会人、会议室审批流。

**验收**：部门配好周会后，下周自动出现会议且参会人正确；会上派的 TODO 出现在被指派人任务里并带截止时间；外部人扫码能签到但看不到任何内部资料。

### F11 AI 能力

**目标**：AI 不是一个聊天框，而是嵌在流程里的若干具体动作。

#### F11.1 助手（悬浮窗 + `/mobile`）

**只读工具 20 个**：`list_projects`、`project_progress`、`project_risks`、`project_tasks`、`project_weekly`、`project_files`、`read_project_doc`、`project_reports`、`list_meetings`、`group_options`、`weekly_status`、`daily_status`、`overdue_tasks`、`my_today`、`my_tasks`、`my_ranking`、`team_ranking`、`my_work_schedule`、`search_knowledge`、`search_sop`

**动作 14 类**（全部先生成确认卡，人点了才执行）：`MEETING_CREATE`、`MEETING_PUBLISH`、`MEETING_NOTIFY`、`WEEKLY_SEND_GROUP`、`WEEKLY_CHASE`、`TASK_CREATE`、`TASK_PATCH`、`OVERDUE_CHASE`、`NOTIFY_BROADCAST`、`DAILY_SUBMIT`、`WEEKLY_SUBMIT`、`WORK_SCHEDULE_SET`、`DAILY_CHASE`、`RISK_ALERT`

**写进提示词的硬约束**（改动这些等于改产品行为，务必谨慎）：
1. 输出契约：每次只输出**一个 JSON 对象**（`tool` / `reply` / `action` 三选一），禁止其它文字。
2. **查 ≠ 催**：用户只问「谁没交」，只准查；只有明说「催/提醒/发」才准出动作。
3. **不编造**：人名、数值、日期只能来自工具返回；名单必须实测，不得凭空指人。
4. 写操作前先核实事实；信息不全先追问（一次只问 1–2 个最关键的点）。
5. 排名口径：工时榜与日报篇数榜是两个榜，分开说；未指定时段默认本月。
6. 项目上下文：有「当前项目档案」时优先依档案回答，分派任务时 `assigneeName` 必须是档案里的人。

#### F11.2 项目上下文对话

~~项目详情页内的独立「AI员工」tab~~ **已于 2026-11-08 下线**。项目上下文能力保留：在项目详情页使用首页悬浮小助手时，前端自动带 `pageContext.projectId`，后端注入该项目档案（成员、文档、文件、日报）并放开项目范围工具（`project_files` / `read_project_doc` / `project_reports`），成员档同样可用。

**验收**：改 `prompts/PROMPTS.md` 保存后无需重启即生效；AI 说出的任何人名/数字都能在工具返回里找到出处。

### F12 钉钉集成与消息触达

### F15 保密与合规

> 详细批复记录见 `docs/guard-prd.md`（13 条决策点已锁定）。

| 机制 | 规则 |
| --- | --- |
| 保密项目开关 | **仅 ADMIN** 可拨 |
| NDA 签署 | 进入保密项目即需在线签署；形式为「我已阅读」按钮（不做手写姓名/签名） |
| NDA 版本化 | 全站一份模板，改正文即升版本；签署记录绑定版本；改版不强制重签 |
| 访问留痕 | 记录：进入保密项目详情、查看/下载其文档与文件。**管理员也记**，但不拦 |
| AI 可答范围 | 保密项目不进入 AI 检索范围：助手 `search_knowledge` / `search_sop` 按本人可见性过滤，未签 NDA 的非成员检索不到。（`guard-prd.md` 里规划的「独立 AI 问答页，仅 ADMIN/DEPT_LEADER」**尚未实现**，当前入口是助手） |
| 群发暂停 | 保密项目的每日进展不群发到钉钉群 |
| 首页收敛 | 保密项目进展不对非成员显示 |
| 项目规则 | 只发站内信提醒未阅，不走钉钉私聊；修订不强制重阅 |

| AI | `AiCallLog` |

**约定**：所有表 `cuid` 主键；软删除用 `deletedAt` 或状态位；时间戳统一 `createdAt/updatedAt`。

## 9. 边界：明确不做的事

| 不做 | 原因 |
| --- | --- |
| 音视频会议、屏幕共享 | 走钉钉原生能力 |
