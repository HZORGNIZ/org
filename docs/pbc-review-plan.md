## 0. 本次已确认的口径（2026-11-08 用户拍板）

1. **评分规则**：成员自评只是过程，上级复核时**可逐条修改分数**，**以领导复核（定稿）后的分数作为该成员当月 PBC 最终分数**。
2. **审核入口**：放在 **工作管理（`/reports`）→ PBC 页签**下，新增「**待我审核**」子视图。
3. **历史记录**：查看历史月份 PBC 时，必须能看到**自评分、上级评分、最终得分**及全部明细。
4. **首页排行**：11 月展示 **10 月（上个月）** 的 PBC 排行。
5. **自评不限时**：**去掉自评时间窗口**，历史月份随时可补自评、可改自评；只有「上级已定稿」的月份才锁死（这点保留，否则定稿分数会被事后改写）。**上级审核随之也不限时**——自评随时能补，审核自然不能卡窗口，只在列表里标逾期天数。

## 1. 先说结论

你提的三件事，**后端逻辑八字已经有一撇，缺的是「人能找到的入口」和「结果的呈现」**：

| 你的诉求 | 代码现状 | 真实缺口 |
| --- | --- | --- |
| 上级审核页面「没有」 | `POST /pbc/leader-review` 已实现，`PbcViewerDialog` 里已有逐条评分 + 定稿 | ① **入口文案指错地方**；② 团队表格里没有任何考核维度，看不出谁待评分 |
| 自评页面「看不到」 | `POST /pbc/self-review` 已实现，「我的计划」里有自评区 | 自评区被 `v-if="canSelfReview"` 包着，而 `canSelfReview` 依赖自评窗口 → **窗口一关整块消失**（11-06 起就看不到 10 月的自评了） |
| 历史月随时可补自评 | `selfReview()` 里有硬校验 `if (!selfWin.open) throw '自评仅在 X 时间段内开放'` | 后端直接拒绝，不是前端藏起来的问题 |
| 上月自评分/领导评分/最终得分要展示 | 数据都存了（`selfTotal`/`leaderTotal`/逐条 `selfScore`/`leaderScore`/`selfSummary`/`leaderComment`/时间） | 只在「已定稿」时展示少量；**自评总述、提交时间、打分上级、明细在只读态都没露出来** |
| 排行按上月打分展示 | `ranking` 只取 `LEADER_DONE`，逻辑正确；首页自动取最近定稿月 | **全站 0 条定稿 → 排行永远是空**；排行榜默认月是「当前月」，11 月必然空 |

## 2. 五个根因（按严重度排序）

### 根因 1｜通知把上级指到了一个已消失的入口 ⚠️最致命

`pbc.service.ts` → `notifySelfReviewToLeader()` 的文案写的是：

> 登录 MyOrgniz →「部门管理」→ PBC → 打开该成员即可逐条评分并定稿。

但菜单里的「部门」早已并进「管理后台 → 部门管理」，而后台那个 tab 里**没有 PBC**；带 PBC 的 `DepartmentView` 只能在首页「我的部门」点进去。上级照着通知找，必然找不到——这就是你说的"我现在也没有看到"。

### 根因 2｜团队 PBC 表格没有考核维度

`ReportsView.vue` 团队视角表格现有列：成员 / 部门 / 状态（计划审批）/ 分解 / 合计分 / 事项数 / 更新时间。
**没有**：考核状态、自评分、最终得分，也没有「评分」按钮。上级即便打开了这个表，也看不出谁在等他评分。

### 根因 3｜打分上级可能根本看不到被评分人

`listForViewer()` 非 ADMIN 时只返回「我所领导的部门」的成员；没有部门直接返回空数组。
但「打分上级」候选（`leaderOptions`）里明确包含**各部门负责人 + 所有管理员**。一旦成员选了跨部门的上级，这位上级在团队表里根本查不到此人，哪怕 `canLeaderReview` 逻辑本身是对的。

### 根因 4｜自评被时间窗口硬卡死（后端拒绝，不只是前端隐藏）

后端 `selfReview()` 里有两道硬校验：

```ts
if (row.reviewStatus === 'LEADER_DONE') throw ...   // 已定稿不能改 —— 这条要保留
if (!sw.open) throw `自评仅在 ${sw.windowText} 时间段内开放`;   // 这条要去掉
```

`selfReviewWindow()` 的规则是「某月月末 3 天 ~ 次月 5 号」（ADMIN 豁免）。10 月的窗口是 **10-29 ~ 11-05**，今天 11-08 已关 —— 所以 10 月那 32 人**在接口层就被拒了**，前端怎么改都没用。同时 `getMine()` 的 `canSelfReview` 也带了 `selfWin.open`，于是「我的计划」里自评整块 `v-if` 直接不渲染，连已有的自评分、自评总述、提交时间都看不到。

### 根因 5｜排行榜默认落在当前月

`PbcRanking` 直接绑 `pbcMonth`（默认 `2026-11`）。11 月自评 11-28 才开、12 月初才定稿，所以进「排行榜」看到的是空表。

## 3. 改动方案

### 3.1 交互结构：PBC tab 下扩成 4 个子视图

现在只有两个 radio：`我的计划 / 排行榜`。改成四个（入口就在你指定的**工作管理**菜单 → PBC 页签下）：

```
左侧菜单「工作管理」→ [日报] [周报] [PBC 月计划] [日报看板] [工时统计]
                                       ↓
              ┌──────────────────────────────────────────────┐
              │ 我的计划 │ 我的自评 │ 待我审核 │ 排行榜        │
              └──────────────────────────────────────────────┘
                   ↑          ↑          ↑         ↑
              计划填写+  逐条自评+  上级复核  最近定稿月
              考核结果只读  总述+上级  可改分数   排行
                        提交时间  定稿为最终分
```

- 「待我审核」只对**有审核任务的人**显示（我是某人的打分上级，或 ADMIN），其他人看不到这个页签。
- 视图状态写进 URL（`?tab=pbc&view=review`），钉钉消息 / 站内信可以直接跳进来。
- 审核语义：上级在「待我审核」里**逐条复核并可修改分数**，提交定稿后该分数即成员当月 PBC 最终得分（沿用现有 `leader-review` 接口，不改评分逻辑）。

### 3.2 「我的计划」：加一块永久展示的「考核结果」

| 展示项 | 数据来源 | 展示条件 |
| --- | --- | --- |
| 自评分合计 | `selfTotal` | `reviewStatus != NOT_STARTED` |
| 逐条自评分 / 自评理由 | `items[].selfScore / selfReason` | 同上 |
| 自评总述 | `selfSummary` | 同上 |
| 自评提交时间 | `selfAt` | 同上 |
| 打分上级 | `pbcLeaderName` | 同上 |
| 最终得分 | `leaderTotal` | `LEADER_DONE`，否则显示「待上级评分」 |
| 逐条上级评分 / 评语 | `items[].leaderScore / leaderComment` | `LEADER_DONE` |
| 整月总评 | `leaderComment`（Pbc 表字段） | `LEADER_DONE` |
| 定稿时间 | `leaderAt` | `LEADER_DONE` |

**关键改动**：自评区只有两种情况——**可编辑**（计划已提交/已批、有事项、上级未定稿，**不限月份、不限时间**）和**只读**（已定稿）。不再有「窗口关了整块消失」这回事。

### 3.3 「我的自评」：独立成页，随时可补、可改

- 表头：月份、自评合计、提交时间、打分上级（可改）、状态
- 状态只有三种：**待自评 / 已自评（待审核） / 已定稿（只读）**
- 表体：逐条「事项 / 分值 / 自评分 / 自评理由」，自评分不能超过该条分值
- 底部：整月自评总述 + 「提交自评 / 更新自评」
- **任意历史月都可进入并提交**，界面标注「补录 2026-10」这类提示，不再出现「自评将在 X 日开放」的拦截
- 原窗口日期改为一行**参考提示**：「原定自评期 10-29 ~ 11-05，已过仍可补录」，不再阻断操作
- 已定稿的月份：只读 + 提示「已由 XX 于 X 日定稿，如需更正请联系管理员撤销」

### 3.4 「待我审核」：上级审核工作台（新增页面）

这是你要的"上级点评复核页面"。布局：桌面左名单右明细，手机单列。

```
┌─────────────────┬──────────────────────────────────────────┐
│ 待我审核 (3)     │  曲帅潼 · 互联网软件研发部 · 2026-10      │
│ ┌─────────────┐ │  自评 60 分 · 11-01 提交                  │
│ │ 曲帅潼  60分 │ │ ┌──────────────────────────────────────┐ │
│ │ 书书    —    │ │ │事项│分值│自评│自评理由│复核评分│评语│ │
│ │ 孙敏惠  0分  │ │ │…  │ 20 │ 15 │ …     │ [15]  │ … │ │
│ └─────────────┘ │ └──────────────────────────────────────┘ │
│ 已定稿 (筛选)    │  整月总评 [___________________________]  │
│                 │  实时合计：58 / 100      [提交复核并定稿] │
└─────────────────┴──────────────────────────────────────────┘
```

- 左侧列表支持筛选：待审核 / 已定稿 / 全部，可按月份切（**默认「全部月份」**，因为补录会让 10 月的老账同时涌进来）；顶部 KPI「待我审核 X 人」
- 右侧逐条**复核打分**：默认带入自评分，**可修改，不高于该条分值**；每条可填复核评语
- 实时合计；提交前二次确认：**定稿后该分数即成员当月 PBC 最终分数，成员不可改、你不可再改**（除非已开撤销）
- 定稿后右侧切为只读结果态，并显示定稿时间
- **批量兜底**：补自评放开后，一个上级可能一次面对 20+ 条待审核（10 月就有 32 人补），列表需分页 + 「上一条 / 下一条」串行处理，避免上下滚
- 复用现有 `PbcViewerDialog` 的评分交互，避免两套逻辑分叉

### 3.5 团队 PBC 表格：补考核列 + 评分入口

| 变更 | 内容 |
| --- | --- |
| 新增列 | 考核状态（未自评 / 待审核 / 已定稿）、自评分、最终得分 |
| 新增筛选 | 考核状态；「只看待我审核」快捷开关 |
| 新增操作 | `canLeaderReview` → **「审核」**按钮（进审核工作台）；`LEADER_DONE` → 「查看结果」 |
| 顶部 KPI | 待我审核 X 人 · 未自评 Y 人 · 已定稿 Z 人 |

### 3.6 排行榜（口径已确认：11 月展示 10 月排行）

| 变更 | 内容 |
| --- | --- |
| 默认月份 | **上个月**（当前是 11 月 → 默认 2026-10）；若上月无任何定稿，回退到最近一个有定稿的月份（新增 `GET /pbc/ranking/months`） |
| 月份选择 | 下拉只列有定稿的月份，避免选到空月 |
| 列 | 名次 / 成员 / 部门 / **最终得分（领导复核后）** / 自评分 / 差值（可选） |
| 标题 | 「2026 年 10 月 PBC 排行 · 按上级复核最终得分」 |
| 空态 | 分两种：「该月还没有定稿评分」vs「全站还没有任何定稿评分」 |

首页 PBC 榜沿用 `latest-ranking`（已自动取最近定稿月），只改空态文案与点击跳转（点进 PBC 排行榜）。

### 3.7 通知与提醒

| 项 | 现状 | 改法 |
| --- | --- | --- |
| 自评完成通知上级 | 已有钉钉私聊，**文案指错入口** | 改为「工作管理 → PBC → 待我审核」，并附直达链接 `/reports?tab=pbc&view=review` |
| 定稿通知成员 | 已有钉钉私聊 | 文案改为「工作管理 → PBC → 我的计划 → 考核结果」，附链接 |
| **补录降噪（新增）** | 现在每提交一次自评就发一条钉钉 | 32 人集中补录会把上级钉钉刷爆。**改法**：非窗口期内提交的自评，按「上级 + 日期」汇总成 1 条（如「今日新增 12 人自评待审核，共 27 人待审核」），窗口期内仍逐条即时通知 |
| 自评开启提醒 | **没有** | 保留（P2）：月末倒数第 3 天提醒未自评的人——但文案改为「本月自评开始了，也可随时补录」，不再是硬截止 |
| 待评分催办 | **没有** | （P2）次月 1 号 / 3 号，给还有待审核的上级发提醒，带人数 |

## 6. 数据与兼容

- **不需要 schema 迁移**：`Pbc` 表已有 `reviewStatus` / `pbcLeaderId` / `selfSummary` / `selfTotal` / `selfAt` / `leaderTotal` / `leaderComment` / `leaderAt`；逐条分数存在 `items` JSON 里（`selfScore`/`selfReason`/`leaderScore`/`leaderComment`）。
- 撤销定稿只改状态字段，不需要新表；若要做**撤销留痕**，再加一张 `PbcReviewLog`（谁在什么时候撤了谁的哪个月）。
- 历史数据不动：10 月那 3 条 `SELF_DONE` 会自然出现在「待我审核」里。
- **放开自评的即时影响**：10 月 32 人补录后，`reviewStatus` 会变 `SELF_DONE`，其打分上级的「待我审核」会一次性涌入 20+ 条（按上级分布）。这是预期行为，但**排行仍然要等上级定稿才出数**，需要提前跟大家说清楚。

## 8. 验收标准

1. 用 `书书` 登录 → **工作管理 → PBC** → 出现「待我审核」，能看到曲帅潼（自评 60 分），逐条复核并可修改分数，定稿成功。
2. 用 `曲帅潼` 登录 → PBC → 切到 2026-10（历史月）→ **不点任何按钮就看见**自评分 60、自评理由、自评总述、提交时间、打分上级，以及领导复核的最终得分与逐条复核评分/评语。
3. 定稿后，`曲帅潼` 的 2026-10 PBC 最终分 = 领导复核定稿分数，收到钉钉私聊，链接点开直达该月考核结果。
4. 首页 PBC 榜出现 **10 月排行**，标题带「2026 年 10 月」，名次按领导复核最终得分。
5. PBC → 排行榜，默认落在 2026-10（不是空白的 11 月），可切到其它有定稿的月。
6. 团队表能筛出「待我审核」，并直接点「审核」进入工作台。
7. 跨部门场景：把某成员的打分上级设为非本部门管理员，该上级仍能在「待我审核」看到他。
8. **10 月补录**：11-08 之后用 `曲帅潼` 登录 → PBC → 切 2026-10 → 自评区**可编辑**（不再是只读/消失），改分并提交成功，状态变「已自评，待审核」。
9. **补录不刷屏**：多人同日补录后，某上级当天只收到 1 条汇总钉钉，且数量正确。
10. **定稿锁**：已定稿的月份，成员打开自评是只读并有撤销提示，直接调接口也返回「已定稿不能再改自评」。

## 10. 回归风险

| 风险 | 说明 |
| --- | --- |
| 部门页 PBC tab 也调 `listForDepartment` | 本次只放宽 `listForViewer`（团队视角），`listForDepartment` 的可见性判定不动，避免部门内互看被越权 |
| 四个子视图共用 `pbcMonth` | 切月要同步刷新「考核结果 / 待我审核 / 排行」，注意别只刷一个 |
| 自评只读区与可编辑区并存 | 同一份数据两处渲染，必须共用同一份计算属性，避免分数不一致 |
| 钉钉文案里的链接 | `APP_WEB_BASE_URL` 为空时默认 `https://hzai.work`，改链接要保留这个兜底 |
| **自评反复修改** | 领导已看到 60 分、成员又改成 80，领导复核时会看到新分数。处理：`selfAt` 刷新，「待我审核」列表标「自评已更新」；分数以领导提交定稿那一刻的最新值为准 |
| **放开窗口后旧数据被改写** | 任何历史月都能改自评，只靠「已定稿」这一道锁。若担心追溯性，可加「定稿后 ADMIN 撤销才可改」的提示与留痕（见 §7 第 1 项） |
| **补录集中涌入** | 32 人补录 → 上级待审核激增，工作台必须分页 + 串行操作，否则一次渲染几百行卡顿 |
